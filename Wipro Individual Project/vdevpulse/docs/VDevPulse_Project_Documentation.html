1. Project Overview & Objectives

1.1 Project Description

VDevPulse is a system daemon written in modern C++17 that creates a virtual Linux character device interface (at /tmp/vdevpulse) and continuously samples CPU, RAM, and uptime metrics directly from Linux kernel synthetic filesystems (/proc/stat, /proc/meminfo, /proc/uptime). It provides applications with standard POSIX device file operations (open, read, write, close) along with virtual IOCTL command handling and thread-safe logging.

1.2 Problem Context & Motivation

Embedded Linux nodes in industrial automation, automotive controllers, and edge gateways require constant monitoring of resource utilization to avoid system brownouts, thrashing, and process starvation. While several monitoring tools exist, they have practical limitations in embedded deployment:

Tool / Approach Operational Characteristic Key Limitation in Embedded Systems
top / htop Interactive terminal user interface Cannot be programmatically queried as a standard character device stream.
Python / Go daemons User-space background scripts Significant memory footprint (50–200 MB RSS), runtime interpreter dependencies.
Prometheus Node Exporter HTTP/TCP metrics exporter Requires network stack overhead, socket listeners, and scrape configurations.
Native Kernel Modules (.ko) In-kernel C character drivers Requires root compilation against kernel headers; errors cause kernel panics.
VDevPulse (This Project) Native C++17 POSIX daemon Zero external dependencies, < 15 MB RSS, standard POSIX device interface.

1.3 Scope of the Project

  • In Scope: Creation of virtual character device node using POSIX FIFO pipes; real-time parsing of /proc/stat, /proc/meminfo, and /proc/uptime; virtual IOCTL command dispatch (0x8001, 0x8002, 0x8003); dynamic JSON policy parsing; thread-safe multi-level logging; automated CMake CTest suite; systemd service configuration.
  • Out of Scope: Kernel-space driver compilation requiring insmod, eBPF in-kernel tracing, and remote network telemetry broadcasting.

3.3 Component Responsibilities

  • DeviceManager: Handles creation, opening, non-blocking reading, writing, and deletion of the FIFO device node, and maintains the internal device operational state.
  • TelemetryMonitor: Reads raw lines from /proc/stat, /proc/meminfo, and /proc/uptime, parses key fields, computes utilization ratios, and renders the terminal dashboard.
  • Logger: Singleton log engine ensuring synchronized multi-threaded log writes to both console and vdevpulse.log.
  • ConfigParser: Reads runtime configuration from JSON format, falling back safely to compiled defaults if the file is absent.

4. Implementation Details

4.1 Telemetry Parsing Mechanics

CPU Metric Calculation

The daemon reads the aggregate cpu line from /proc/stat:

std::ifstream proc_stat("/proc/stat");
if (proc_stat.is_open()) {
    std::string cpu_label;
    long user, nice, system, idle, iowait, irq, softirq, steal;
    proc_stat >> cpu_label >> user >> nice >> system >> idle >> iowait >> irq >> softirq >> steal;
    long idle_time = idle + iowait;
    long non_idle_time = user + nice + system + irq + softirq + steal;
    long total_time = idle_time + non_idle_time;
    if (total_time > 0) {
        t.cpu_usage_pct = (static_cast<double>(non_idle_time) / total_time) * 100.0;
    }
}

RAM Metric Calculation

The daemon reads /proc/meminfo and extracts MemTotal, MemFree, and MemAvailable. It uses MemAvailable to calculate available memory, as it takes into account reclaimable page caches and inactive memory.

long usable_free_kb = (available_kb > 0) ? available_kb : free_kb;
t.memory_total_mb = total_kb / 1024;
t.memory_free_mb = usable_free_kb / 1024;
t.memory_used_mb = t.memory_total_mb - t.memory_free_mb;
t.memory_usage_pct = (static_cast<double>(t.memory_used_mb) / t.memory_total_mb) * 100.0;

4.2 Virtual Device Driver & IOCTL Emulation

The virtual character device is created using POSIX mkfifo(). To prevent the daemon from blocking when writing without a connected reader, the file descriptor is opened with O_RDWR | O_NONBLOCK. 

bool DeviceManager::openDevice() {
    device_fd_ = open(device_path_.c_str(), O_RDWR | O_NONBLOCK);
    if (device_fd_ < 0) return false;
    state_ = DeviceState::RUNNING;
    return true;
}

4.3 Technical Issues Encountered & Resolutions

Issue Subsystem Root Cause Applied Solution
DEV-01 DeviceManager open() in write-only mode blocked indefinitely without an attached reader. Used O_RDWR | O_NONBLOCK flags on the FIFO node.
DEV-02 ConfigParser Daemon threw file access errors when optional configuration file was missing. Added std::filesystem::exists() check with default parameter fallback.
DEV-03 Logger Buffered log outputs were delayed in terminal output. Flushed each entry explicitly with std::endl.

6. Deployment, Limitations & Conclusion

6.1 Production systemd Service Configuration

To run VDevPulse as a background service on Linux systems, install the following service definition:

Service File: /etc/systemd/system/vdevpulse.service

[Unit]
Description=VDevPulse Linux Virtual Device & System Telemetry Daemon
After=network.target local-fs.target

[Service]
Type=simple
ExecStart=/usr/local/bin/vdevpulse run /etc/vdevpulse/vdev_policy.json
Restart=on-failure
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target

6.3 System Limitations & Future Work

  • Limitation: The virtual device node is implemented as a user-space POSIX FIFO rather than an in-kernel character driver (cdev).
  • Limitation: Telemetry collection is currently limited to the local host machine.
  • Future Work: Port the device manager to a native Linux Kernel Module (.ko) using cdev_add, file_operations, and kernel IOCTL handlers.
  • Future Work: Add gRPC export capability to broadcast telemetry data to remote monitoring systems.
Conclusion: VDevPulse successfully demonstrates the integration of Linux system programming, POSIX character device interfaces, kernel procfs parsing, and modern C++17 architecture in a clean, resource-efficient package suitable for embedded Linux environments.
